    My actual BOLT work
    Documented tasks and screen evidence → the patterns demonstrated here.
    I worked as a B2B contractor in BOLT Healthcare’s Customer Success team. This demo illustrates my implementation and configuration work; it does not claim I developed BOLT’s underlying platform.
    1. Input configuration and labels
    The weekly task report for 5–11 April 2026 records PDF-engine input updates and labeling. Bolt Work Proof Combined 3.pdf, page 12, shows an input-label editing dialog.
    Try it: inspect each form field and its required/optional rule.
    2. Intake field mapping
    The same report records dynamic intake-field mapping. Bolt Work Proof Combined 2.pdf, page 13, shows a field-configuration table; Combined 3, page 13, shows a configuration screen.
    Try it: change a field’s output target, run validation, then restore the mapping and compare the JSON output.
    3. Output checks and conditional inputs
    The report records data validation and workflow testing. Bolt Work Proof Combined 2.pdf, pages 11–12 and 16, shows configured form inputs and dropdowns.
    Try it: select “Two Chronic Conditions,” leave the additional field blank and submit. The result identifies the missing conditional input.
    4. Signature-link configuration
    Bolt Work Proof Combined 2.pdf, page 17, shows a Links Manager with several signer entries. The sequential flow here is an illustrative implementation, rather than a verified reproduction of BOLT’s exact signing rules.
    Try it: save an applicant signature, submit a passing form and complete the sample signer steps.
